ڨيلو (Velo)

متصفح أندرويد أصلي — Native Android Browser

ڨيلو هو مشروع متصفح إنترنت لنظام Android، يُطوَّر باستخدام Kotlin، ويهدف إلى توفير تجربة تصفح عربية سهلة وحديثة، مع إمكانية التوسع مستقبلًا لدعم لغات متعددة وميزات متقدمة.

يعتمد المشروع في مرحلته الأولى على Android WebView لعرض صفحات الويب، وعلى Google محركًا افتراضيًا للبحث، مع تصميم يسمح بإضافة محركات بحث أخرى مستقبلًا.

---

1. معلومات المشروع

- اسم التطبيق بالعربية: ڨيلو
- اسم التطبيق بالإنجليزية: Velo
- اسم مستودع GitHub: "Velo"
- معرّف الحزمة: "com.velo.browser"
- لغة البرمجة: Kotlin
- نظام التشغيل المستهدف: Android
- الحد الأدنى لإصدار Android: Android 8.0 (API 26)
- تقنية عرض صفحات الويب: Android WebView
- محرك البحث الافتراضي: Google
- لغة الواجهة الأولى: العربية
- دعم اللغات مستقبلًا: الإنجليزية وغيرها
- نظام البناء: Gradle
- منصة البناء الآلي: GitHub Actions
- صيغة التطبيق الأولية: APK

---

2. أهداف المشروع

1. إنشاء متصفح أندرويد أصلي، وليس تطبيق ويب مغلفًا داخل WebView.
2. تطوير التطبيق باستخدام Kotlin وواجهات Android الأصلية.
3. البدء بأقل عدد عملي من الملفات لإنتاج أول APK قابل للتثبيت.
4. تنفيذ البناء والاختبارات آليًا عبر GitHub Actions.
5. جعل العربية اللغة الأساسية للواجهة مع دعم اتجاه RTL.
6. فصل النصوص عن كود التطبيق لتسهيل إضافة لغات جديدة.
7. تطوير الميزات تدريجيًا بعد نجاح الإصدار الأول.
8. تقليل الاعتماد على الخدمات المدفوعة والخوادم الخاصة.
9. الحفاظ على بنية قابلة للصيانة والتوسع دون تعقيد مبكر.
10. مراعاة الأمان والخصوصية وتوافق التطبيق مع إصدارات Android المدعومة.

---

3. المعمارية التقنية

3.1 التطبيق

- Kotlin هي لغة البرمجة الأساسية.
- استخدام Android Views لبناء واجهة المستخدم.
- استخدام Android WebView لعرض المواقع.
- استخدام موارد Android لإدارة النصوص والترجمات.
- حفظ الإعدادات والبيانات المحلية على الجهاز عندما تكون هناك حاجة إليها.

3.2 محرك البحث

سيكون Google محرك البحث الافتراضي.

يجب أن يميّز شريط العنوان بين عناوين المواقع وعبارات البحث، بحيث تُفتح الروابط مباشرةً وتُرسل عبارات البحث إلى Google.

يجب تصميم إدارة محرك البحث بحيث تسمح بإضافة محركات أخرى مستقبلًا، مثل Bing وDuckDuckGo، دون إعادة تصميم شريط العنوان بالكامل.

3.3 محرك عرض المواقع

سيستخدم الإصدار الأول Android WebView المتاح على جهاز المستخدم.

هذا يعني أن تحديث محرك العرض يعتمد على مزوّد WebView وإصداره على الجهاز، ولا يعني أن التطبيق يتضمن نسخة مستقلة كاملة من Chromium.

يوجد توجه مستقبلي منفصل لدراسة إمكانية إنشاء أو دمج مكوّن عرض مستقل يعتمد على Chromium، لكن هذا ليس جزءًا من الإصدار الأول ولا يجوز اعتباره ميزة منفذة.

3.4 البناء والتوزيع

ستُستخدم GitHub Actions من أجل:

- إعداد JDK وأدوات Android SDK المطلوبة.
- إعداد Gradle بإصدار محدد ومتوافق مع المشروع.
- تشغيل الاختبارات المتاحة.
- بناء التطبيق.
- التحقق من نجاح البناء.
- حفظ ملف APK الناتج ضمن Artifacts لتنزيله.

يمكن نشر الإصدارات المستقرة لاحقًا في GitHub Releases.

لن يحتاج البناء إلى كمبيوتر محلي أو بيئة تطوير مثبتة على هاتف المستخدم.

4. سياسة الملفات والتطوير

- يبدأ المشروع بأقل عدد عملي من الملفات.
- لا تُنشأ ملفات إضافية دون حاجة تقنية واضحة.
- تُفصل المسؤوليات إلى ملفات مستقلة عندما يستدعي حجم المشروع ذلك.
- تُفحص الملفات الموجودة قبل تعديلها لتجنب التكرار أو التعارض.
- لا تُفترض محتويات الملفات الحالية دون الاطلاع عليها.
- تُختبر كل دفعة تغييرات قبل الانتقال إلى الدفعة التالية.
- تُراجع توافقات المشروع ككل، وليس الملف المعدل وحده.
- يُعالج السبب الجذري للأخطاء بدل إضافة ترقيعات غير مدروسة.
- يُحافظ على القرارات المعتمدة في هذا التوثيق، وتُحدّث الوثيقة عند اعتماد تغييرات جديدة.

---

5. تنظيم اللغات

ستُدار نصوص الواجهة من خلال موارد Android.

الموارد المستهدفة:

- "app/src/main/res/values/strings.xml"
- "app/src/main/res/values-ar/strings.xml"

ستكون العربية هي اللغة الأساسية عند بداية المشروع، مع ضبط اتجاه الواجهة من اليمين إلى اليسار.

عند إضافة الإنجليزية مستقبلًا، ستُضاف مواردها في مسار مستقل، مثل:

"app/src/main/res/values-en/strings.xml"

يجب عدم توزيع النصوص الظاهرة للمستخدم على هيئة سلاسل ثابتة داخل كود Kotlin إلا عند وجود سبب تقني مبرر.

6. مراحل التنفيذ

المرحلة الأولى: النواة الأولية

الهدف هو إنتاج أول APK صالح للتثبيت.

تشمل:

- إنشاء هيكل Android الأساسي.
- إعداد Kotlin وGradle.
- إعداد AndroidManifest.
- إنشاء الشاشة الرئيسية.
- عرض المواقع باستخدام WebView.
- شريط عنوان يدعم الروابط والبحث عبر Google.
- أزرار الرجوع والتقدم وإعادة التحميل.
- إعداد GitHub Actions للبناء.
- تنزيل APK واختباره على جهاز Android.

لا تُعتبر المرحلة مكتملة إلا بعد نجاح إجراء البناء والتحقق من إمكانية تثبيت التطبيق وتشغيله.

المرحلة الثانية: التبويبات

- فتح تبويبات متعددة.
- التبديل بين التبويبات.
- إغلاق التبويبات.
- إدارة حالات التصفح والتنقل بصورة صحيحة.

المرحلة الثالثة: سجل التصفح والإشارات المرجعية

- حفظ سجل التصفح محليًا.
- إضافة المواقع إلى الإشارات المرجعية.
- عرض العناصر المحفوظة.
- حذف السجل أو عناصر محددة.

المرحلة الرابعة: التنزيلات

- تنزيل الملفات من المواقع المدعومة.
- عرض حالة التنزيل.
- معالجة الأخطاء والروابط غير المدعومة.
- مراعاة صلاحيات النظام وحماية الملفات.

المرحلة الخامسة: الخصوصية والإعدادات

- مسح سجل التصفح.
- مسح بيانات المواقع وملفات تعريف الارتباط وفق الخيارات المحددة.
- إعدادات الصفحة الرئيسية.
- اختيار محرك البحث.
- إعدادات المظهر واللغة.
- مراجعة الأذونات ومخاطر WebView.

المرحلة السادسة: التثبيت والتوزيع

- توسيع الاختبارات.
- إصلاح أخطاء البناء والتشغيل.
- إعداد إصدار قابل للتوزيع.
- حفظ APK في GitHub Releases عند اعتماد الإصدار.
- التحقق من إعدادات توقيع التطبيق وإدارة مفتاح التوقيع بأمان.

المراحل أعلاه خطة مستقبلية وليست إعلانًا عن اكتمال أي ميزة.

7. الأمان والخصوصية

- استخدام HTTPS عند توفره.
- عدم تعطيل التحقق من شهادات TLS.
- عدم السماح بمحتوى غير آمن دون ضرورة واضحة.
- عدم تمكين JavaScript إلا وفق احتياجات التصفح المدروسة.
- تجنب واجهات JavaScript الأصلية غير الضرورية.
- ضبط التعامل مع الروابط الخارجية والتنزيلات.
- مراجعة سياسات ملفات تعريف الارتباط وبيانات المواقع.
- عدم جمع بيانات المستخدم أو إرسال سجل تصفحه إلى خادم خاص دون ميزة واضحة وموافقة مناسبة.
- حماية مفاتيح توقيع التطبيق وأسرار GitHub وعدم تضمينها في المستودع.

8. سياسة الخوادم والتكاليف

لا يتطلب الإصدار الأول خادمًا خاصًا لعرض المواقع أو تنفيذ البحث أو حفظ البيانات المحلية.

ستُستخدم خدمات GitHub للمستودع والبناء الآلي وتوزيع ملفات الإصدار.

قد تتطلب ميزات مستقبلية مثل مزامنة البيانات بين الأجهزة أو الحسابات أو خدمات البروكسي بنية خلفية أو مزود خدمة. ولن تُضاف هذه المتطلبات إلا بعد تحديد الحاجة إليها ودراسة تكلفتها وبدائلها.

2. إنتاج ملف APK صالح.
3. تثبيت التطبيق على جهاز Android متوافق.

6. فتح مواقع الإنترنت باستخدام WebView.

9. عدم وجود أعطال أساسية تمنع استخدام التطبيق.
